# NetBird Deployment Note

Status: running on VM100 with Pi5 PostgreSQL datastore and no VM100 host ports
exposed. Started 2026-09-13.

## Goal

Install NetBird as the next private access layer for the homelab without
bringing back the old VPS NetBird/Coturn/Headscale stack. The first target is a
working control plane and dashboard backed by Pi5 PostgreSQL. A separate public
relay/STUN path remains a follow-up gate, not an assumption.

## Initial Placement

| Component | Placement | Notes |
|---|---|---|
| NetBird dashboard | VM100 | Swarm service `netbird_netbird-dashboard` on `homelab-net`; no published host port. |
| NetBird combined server | VM100 | Swarm service `netbird_netbird-server` on `homelab-net`; no published host port. |

| VPS public allow-list | complete | Added `netbird.dungxbuif.com` to `/root/gateway/dynamic.yml`. Also synchronized the VPS HostSNI allow-list with the active Orange Pi hostnames that were missing. |

## Constraints

- Do not bind VM100 ports directly to the public Internet.
- Do not install NetBird management/dashboard on the VPS.
- Do not add a catch-all TCP router on the shared `443` listener.
- Do not reintroduce Coturn/Headscale/RustDesk while installing NetBird.
- Keep Pi5 as datastore only. Any Pi5 PostgreSQL move must create dedicated
  NetBird databases/roles and update backup coverage.
- Keep existing Orange Pi/VPS Rathole public ingress working.

## PostgreSQL Migration

Before changing `config.yaml`, create a VM100 backup of:

```text
/opt/apps/netbird/config.yaml
Docker volume: netbird_netbird_data
```

Created a dedicated PostgreSQL role and three databases on Pi5:

```text
role: netbird
databases:
  netbird
  netbird_activity
  netbird_idp
```

Then updated NetBird:

```yaml
store:
  engine: "postgres"
  dsn: "host=pgbouncer port=6432 user=netbird password=<secret> dbname=netbird sslmode=disable"

activityStore:
  engine: "postgres"
  dsn: "host=pgbouncer port=6432 user=netbird password=<secret> dbname=netbird_activity sslmode=disable"

authStore:
  engine: "postgres"
  dsn: "host=pgbouncer port=6432 user=netbird password=<secret> dbname=netbird_idp sslmode=disable"
```

NetBird remains on `homelab-net` and must not publish VM100 host ports. The
temporary password files used during migration were removed after verification.

## Verification

Before route conversion:

- VM100 has Docker and Compose support. Verified with `docker-compose 1.29.2`.
- The first bootstrap used host ports `18090`, `18091`, and `3478/udp`; this was removed because it violated the no-unnecessary-exposed-ports rule.

After no-host-port conversion:

- VM100 has no listeners on `18090`, `18091`, or `3478`. Verified with `ss`.
- `netbird_netbird-server` and `netbird_netbird-dashboard` Swarm services run `1/1` on `vm100-prod`.
- NetBird server logs report `Store engine: postgres`,
  `NB_ACTIVITY_EVENT_STORE_ENGINE=postgres`, and Postgres store initialization.
- Pi5 PostgreSQL schema verification returned:
  `netbird tables=39`, `netbird_activity tables=2`, and `netbird_idp tables=13`.
- Orange Pi Traefik resolves Swarm service VIPs such as `netbird-server`,
  `n8n`, and `mypocket-web`, but VIP connections returned `Host is
  unreachable`. Direct task DNS records such as `tasks.netbird-server` work.
  The active edge pattern for one-replica VM100 services is therefore
  `tasks.<service>` DNSRR from the file provider, not published host ports.
- LAN/split route through Orange Pi Traefik returns HTTP `200` for NetBird OIDC and dashboard.
- Forced VPS path `--resolve netbird.dungxbuif.com:443:103.82.21.202` returns HTTP `200` for the OIDC discovery endpoint and dashboard.
- Existing route checks after switching to `tasks.*`: `dungxbuif.com`,
  `ocr.dungxbuif.com`, `n8n.dungxbuif.com`, `money.dungxbuif.com`, and
  `netbird.dungxbuif.com` returned HTTP `200`. `openclaw.dungxbuif.com/`
  returned HTTP `403`, treated as app-level behavior rather than a routing
  regression.
- VPS public route matrix after HostSNI sync: active hostnames return app-level
  responses (`200`, `302`, `401`, or intentional `403`) rather than Traefik
  `404`.

IdP users, MFA reset, and reverse-proxy tokens:

## Rollback

On VM100:

```bash
cd /opt/apps/netbird
docker compose down
```

For PostgreSQL rollback, restore `/opt/apps/netbird/config.yaml` from
`/opt/apps/netbird/backups/config.yaml.bak-pg-20260913-143916`, restore the
`netbird_netbird_data` volume from
`/opt/apps/netbird/backups/netbird_data_sqlite_bak_pg_20260913-143916.tgz`, and
redeploy the Swarm stack from the manager.

If Orange Pi routing was applied, restore the timestamped
`/opt/edge/traefik/dynamic.yml` backup created before the change. If VPS
HostSNI was changed, restore the timestamped `/root/gateway/dynamic.yml` backup.
