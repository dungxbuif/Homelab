# NetBird Deployment Note

Status: control plane running on VM100 with Pi5 PostgreSQL datastore, no VM100
host ports exposed, and external VPS relay/STUN active. VM100 NetBird client is
installed for use as the future LAN routing peer, but it is not enrolled until
a setup key is supplied. Started 2026-09-13; router-peer preparation and
external relay added 2026-09-17.

## Goal

Install NetBird as the next private access layer for the homelab without
bringing back the old VPS NetBird/Coturn/Headscale stack. The first target is a
working control plane and dashboard backed by Pi5 PostgreSQL. The public
relay/STUN path is provided by a small VPS relay container so roaming clients
can still connect when direct peer-to-peer NAT traversal is not enough.

## Constraints

- Do not bind VM100 ports directly to the public Internet.
- Do not install NetBird management/dashboard on the VPS.
- Do not add a catch-all TCP router on the shared `443` listener.
- Do not reintroduce Coturn/Headscale/RustDesk while installing NetBird.
- Keep Pi5 as datastore only. Any Pi5 PostgreSQL move must create dedicated
  NetBird databases/roles and update backup coverage.
- Keep existing Pi5/VPS Rathole public ingress working.

## Planned Runtime

Use the upstream NetBird `v0.78.1` self-hosted generated config with embedded
IdP and combined server, but run it behind the existing homelab edge rather than
the built-in Traefik option.

Initial host-port bootstrap was removed after review. Current NetBird runtime
must not publish VM100 host ports:

```text
netbird_netbird-dashboard -> homelab-net only
netbird_netbird-server    -> homelab-net only
published ports           -> none
```

The combined server uses an external relay/STUN configuration, so its embedded
relay is disabled:

```yaml
server:
  stuns:
    - uri: "stun:netbird-relay.dungxbuif.com:3478"
      proto: "udp"
  relays:
    addresses:
      - "rels://netbird-relay.dungxbuif.com:443"
    secret: "<secret>"
    credentialsTTL: "24h"
```

Runtime files on VM100:

```text
/opt/apps/netbird/docker-compose.yml
/opt/apps/netbird/config.yaml
/opt/apps/netbird/dashboard.env
Docker volume: netbird_netbird_data
Swarm stack file staged from /tmp/netbird-stack.yml
```

Relay files on VPS:

```text
/root/netbird-relay/docker-compose.yml
/root/netbird-relay/relay.env
Docker volume: netbird-relay_relay_data
```

The VPS relay uses the existing wildcard certificate mounted from
`/root/gateway/certs` and a dedicated Traefik TCP router for
`netbird-relay.dungxbuif.com`; it does not add a catch-all SNI rule or bind TCP
`443` directly. UDP `3478` is intentionally published for STUN.

Images are generated from the upstream `getting-started.sh` flow. The combined
server reports version `0.78.1` at runtime, but Docker Hub currently exposes the
combined `netbirdio/netbird-server` image as `latest`; the attempted
`netbirdio/netbird-server:v0.78.1` tag did not exist.

The Pi5 edge route uses path-aware forwarding:

```text

  /signalexchange.SignalExchange/
  /management.ManagementService/
  /management.ProxyService/

Backend paths:
  /relay
  /ws-proxy/
  /api
  /oauth2

Dashboard:
  all remaining paths
```

## PostgreSQL Migration

Before changing `config.yaml`, create a VM100 backup of:

```text
/opt/apps/netbird/config.yaml
Docker volume: netbird_netbird_data
```

Created a dedicated PostgreSQL role and three databases on Pi5:

```text
role: netbird
databases:
  netbird
  netbird_activity
  netbird_idp
```

Then updated NetBird:

```yaml
store:
  engine: "postgres"
  dsn: "host=pgbouncer port=6432 user=netbird password=<secret> dbname=netbird sslmode=disable"

activityStore:
  engine: "postgres"
  dsn: "host=pgbouncer port=6432 user=netbird password=<secret> dbname=netbird_activity sslmode=disable"

authStore:
  engine: "postgres"
  dsn: "host=pgbouncer port=6432 user=netbird password=<secret> dbname=netbird_idp sslmode=disable"
```

NetBird remains on `homelab-net` and must not publish VM100 host ports. The
temporary password files used during migration were removed after verification.

## Onboarding Notes

IdP users, MFA reset, and reverse-proxy tokens:

```text

/go/bin/netbird-server admin token ...
```

It does not expose a first-user creation command in the deployed image. Create
the first administrator and setup keys from `https://netbird.dungxbuif.com/`
after the UI redirects through the embedded IdP. Do not place generated user
passwords or setup keys in repository docs.

## LAN Routing Peer Setup

VM100 is prepared as the preferred routing peer for homelab LAN access:

```text
client version: NetBird 0.78.2
service: netbird.service active/enabled
state: NeedsLogin until setup key enrollment
kernel forwarding: net.ipv4.ip_forward=1
firewall: UFW inactive; FORWARD policy ACCEPT at preparation time
intended route: 10.10.0.0/24
```

Enroll VM100 after creating a setup key in the dashboard:

```bash
sudo netbird up \
  --management-url https://netbird.dungxbuif.com \
  --setup-key <SETUP_KEY> \
  --hostname vm100-router
```

Then create a NetBird network route/resource for `10.10.0.0/24` with
`vm100-router` as the routing peer and allow only the operator device group
to use it. Prefer masquerade/SNAT for this initial LAN-wide route so return
traffic from LAN hosts does not require static routes on MikroTik.

## Rollback

On VM100:

```bash
cd /opt/apps/netbird
docker compose down
```

For PostgreSQL rollback, restore `/opt/apps/netbird/config.yaml` from
`/opt/apps/netbird/backups/config.yaml.bak-pg-20260913-143916`, restore the
`netbird_netbird_data` volume from
`/opt/apps/netbird/backups/netbird_data_sqlite_bak_pg_20260913-143916.tgz`, and
redeploy the Swarm stack from the manager.

If Pi5 edge routing was applied, restore the timestamped
`/home/dungxbuif/edge/traefik/dynamic.yml` backup created before the change. If VPS
HostSNI was changed, restore the timestamped `/root/gateway/dynamic.yml` backup.

For relay rollback, restore the VM100 `config.yaml` backup created before
external relay, force-update `netbird_netbird-server`, remove the VPS
`netbird-relay` Compose project, and remove only the
`netbird-relay.dungxbuif.com` router/service from `/root/gateway/dynamic.yml`.
If LAN DNS should stop pointing relay traffic to VPS, remove the matching
AdGuard rewrite and restart `edge-adguardhome-pi5`.
