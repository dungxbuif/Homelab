# Vault Knowledge Format (OKF v0.2 profile)

This vault is an OKF v0.2 knowledge bundle[^okf-spec]. The bundle root is the vault directory, and the root `index.md` declares `okf_version: "0.2"`. This page records the choices the vault makes on top of the spec. Where they differ, the spec wins.

## 1. Files

| File | Rule |
|---|---|
| `index.md` (any directory) | Reserved. A listing of headings that group bullet links, each with a short description. No frontmatter, except `okf_version` in the root `index.md` |
| `log.md` (`docs/log.md`) | Reserved. `## YYYY-MM-DD` headings, newest first, with prose entries. Entries start with a bold word (**Update**, **Creation**, **Deprecation**) |
| Every other `.md` | A concept document. Needs YAML frontmatter with a non-empty `type` |

Do not name a concept `INDEX.md` or `LOG.md`.

## 2. Frontmatter

```yaml
---
type: Runbook                     # REQUIRED — see vocabulary below
title: "Human title"
description: "One line"
generated:
  by: claude-code/opus-5.5        # actor (§3); human:dungxbuif when hand-written
  at: 2026-10-31T16:00:00+07:00   # last meaningful content change, explicit offset
verified:                          # optional; add when someone re-checks the content
  - by: human:dungxbuif
    at: 2026-11-02T09:00:00+07:00
status: draft                      # draft | stable (default, omit) | deprecated
stale_after: 2027-01-31T00:00:00+07:00
sources:                           # optional provenance, cite with [^id] footnotes
  - id: live-audit-2026-10-31
    resource: /docs/deployments/version-upgrade-2026-10-31.md
tags: [backup]
lifecycle: active                  # vault extension for Project/Service docs only
---
```

- `timestamp` is **not used**. It is replaced by `generated.at`.
- `status` is the *document's* state. A project's or service's runtime state goes in the extension key `lifecycle`: `active | lab | paused | retired | not deployed`.
- `stale_after` defaults by area:

  | Area | `stale_after` |
  |---|---|
  | Current-state pages (STATUS, STACK, host refs, BACKLOG, overview) | +30 days |
  | Plans and specs | +60 days |
  | Projects, services, runbooks, standards | +90 days |
  | Dated deployment evidence | none (point in time) |

- Trust tier is derived from `verified`, never stored as a score. No `verified` means the doc is unverified. Only non-human actors means machine-confirmed. At least one `human:` actor means human-reviewed.

## 3. Actors

| Actor | Use |
|---|---|
| `human:dungxbuif` | Content the owner wrote or confirmed |
| `claude-code/opus-5.5`, `codex/<version>` | Content written by an agent |
| `process:vault-import` | Content that existed before the OKF migration and whose author is unknown |
| `process:<job>` | Content generated by an automated job (for example a CI drift report) |

## 4. Type vocabulary

The spec registers no types. This vault uses the following types (consumers must tolerate others):

`Reference`, `Dashboard`, `Runbook`, `Standard`, `Decision`, `Decision Record`, `Plan`, `Design Spec`, `Deployment Evidence`, `Project`, `Service`, `Backlog`.

## 5. Links

- Use standard markdown links. New content uses bundle-rooted paths that start with `/` (for example `/docs/STACK.md`). Existing relative links stay valid.
- Links are untyped. Describe the relationship in the surrounding prose.
- External evidence goes in `sources` and is cited with footnotes (`[^id]`), not in a `# Citations` section.

## 6. Conformance check

A bundle conforms when every concept has parseable frontmatter with a non-empty `type`, and `index.md`/`log.md` follow §1. Run the check before committing doc changes. The checker belongs in `homelab-ops` CI, not in this vault.

[^okf-spec]: Open Knowledge Format v0.2, GoogleCloudPlatform/knowledge-catalog `okf/SPEC.md`.
