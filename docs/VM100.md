# VM100 Production Compute Host

VM100 (`vm100-prod`, `10.10.0.31`) is the current production compute host for
the user-facing workloads migrated off the Mac mini and retired Proxmox K8s
cluster.

The authoritative point-in-time image, replica, network, and backup inventory
is the dated deployment evidence linked from the [current status page](./STATUS.md)
and [runtime inventory](./deployments/runtime-inventory-2026-10-13.md).
This page keeps the VM100-specific operating model and recovery notes.

VMs `101` and `102` were deleted. Kubernetes and kube-vip residue were removed
from VM100; PostgreSQL remains on Pi5 and was not moved. VM100 joined the
existing Pi5-led Docker Swarm as a worker on 2026-09-12. Production services
were migrated individually to Swarm. The old Compose containers are stopped
and retained only as rollback paths.

## Lifecycle Control

VM100 is represented by the import-only OpenTofu module at
[`../automation/tofu/proxmox/`](../../../projects/homelab-ops/automation/tofu/proxmox/). It is a protected
production object, not a disposable lab VM. The first plan must import VM ID
`100` without destroy or replacement; the second plan after import must be
no-op before OpenTofu is allowed to manage CPU, RAM, disk, or swap sizing.
VMs `101` and `102`, Kubernetes nodes, and kube-vip are outside the active
inventory and cannot be targeted by this module.

Disk was grown online from 80 to 200 GiB on 2026-09-15 without VM restart.
After the 2026-09-15 VM restart, `discard=on` is active. Guest
`sudo fstrim -v /` reported 136.1 GiB trimmed; Proxmox `local-lvm` physical
usage fell from about 83.3 to 66.0 GiB. A pre-restart trim had not reduced
the host pool. See
[GitLab preflight and disk audit](./research/gitlab-vm100-preflight-2026-09-15.md).

Homepage is the first individually verified cutover: its public route now uses
the portless `homepage` Swarm service on `homelab-net`. The old Compose runtime
is retained stopped for rollback after the stability check.

backup must run beside the Omnibus container. The online GitLab wrapper has
been exercised against CE `18.11.11` and records the native archive,

## Routing

The active Pi5 `edge-traefik-pi5` routes these upstreams to VM100:

```yaml
homepage:  http://tasks.homepage:80
ocr:       http://tasks.macocr-proxy:8080
mezonhook: http://tasks.mezonhook:8080
family:    http://tasks.family-tree:3000
openclaw:  http://tasks.openclaw:18789
n8n:       http://tasks.n8n:5678
mypocket:  http://tasks.mypocket-api:8080
netbird:   dashboard http://tasks.netbird_netbird-dashboard:80, server http/h2c tasks.netbird_netbird-server:80
relayhub:  http://relayhub-api:8080
kubekosh:  http://kubekosh:80 (LAN-only middleware)
```

Homepage, `openclaw`, `n8n`, and MyPocket now run as Swarm services on
`homelab-net`.
Their public routes use Swarm DNS service names rather than VM100 host ports.
RelayHub is live as a VM100 Compose runtime. Its API is attached to
`homelab-net` as `relayhub-api`; worker, NATS and Redis stay on private
`relayhub-net`. PostgreSQL remains on Pi5. Admin authentication is
email/password with a secure browser session cookie; the retired Admin bearer
token is not part of the VM100 runtime env.
The experimental manager-side Docker socket proxy and Traefik Swarm provider
were removed after intermittent overlay
reachability caused public `502` responses.
`bds-app` is intentionally not routed through the shared Traefik edge. Public ingress
uses the standalone `bds-cloudflared` connector on VM100. The tunnel container
is attached only to the local `bds-tunnel-net` bridge and targets
`http://bds-app:3000`; it must not join `homelab-net`.
KubeKosh is also intentionally not routed through the VPS shared edge. It uses
Pi5 AdGuard split DNS and the Pi5 Traefik `lan-only` middleware for local
learning access only.
Educates was removed on 2026-09-17 after the generated skeleton proved less
useful than the upstream Kubernetes fundamentals course. The VM100 containers,
local content registry, firewall rules, source directory, and Pi5 route were
deleted. Reinstall from the official upstream workshop when needed.
